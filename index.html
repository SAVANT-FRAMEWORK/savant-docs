    Preamble¶

    This documentation site is not a user manual. It is a constitutional record.

    A constitution does not teach a reader how to operate a state; it proves that the state exists, that its powers are enumerated, that its limits are defined, and that its succession is orderly. The documents collected here perform the same function for the SAVANT FRAMEWORK. Each specification in this archive is written to a single standard: a competent sovereign party, with no prior contact with the author and no access to proprietary tooling, must be able to verify every load-bearing claim from the text alone.

    That standard has three corollaries, and they define what this archive is for.

    First, the architecture is complete. The Sovereign Prompt Operating System (SPOS v1.0) enumerates its six-layer fractal in full. The Sovereign Invocation Protocol (SIP v1.0) enumerates every trigger prefix and every routing decision. The S50-ABSOLUTE governance engine enumerates every checkpoint class and admits no intermediate state between GO and NO-GO. Where a component is planned but not yet filed — the PPA-006 Jurisdiction Compiler, for example — the text says so, in so many words. Completeness here means the boundary of the finished work is drawn exactly, not that the boundary is drawn generously.

    Second, the architecture is governed. Every artifact in this archive is subject to SHA-256 signed go/no-go checkpoints, hash-chained prompt genealogy, and regression detection with signed REGRESSION records. The constitutional authority for all governance decisions is Dr. Christabel Odeta, sole author of all associated intellectual property. Governance is not a department; it is a property of every artifact, enforced by S50-ABSOLUTE at the point of creation.

    Third, the architecture is transferable. The AEGIS-GLOBAL manufacturing specification is written such that a contract manufacturer in Shenzhen and a certified engineer in Kano can read the same page and produce the same node. The universal grant narrative is written such that a funder can underwrite the architecture against falsifiable metrics rather than against claims. Transferability is the difference between a system and a dependency.
